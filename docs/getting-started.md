# 新手上手：从准备到验收

[返回首页](../README.md) · [详细配置](clash-verge.md) · [模板字段](../examples/README.md) · [故障排查](troubleshooting.md)

目标是建立 `设备 → 已可用的加密入口 → 静态 ISP 出口 → 指定网站`，并验证请求确实按这条路径发送。本仓库不提供节点、订阅或商家账号。

## 先分清这些名称

| 名称 | 本指南里的意思 | 容易混淆的地方 |
| --- | --- | --- |
| 入口节点 | 你已经能连接的第一跳代理 | 入口能访问网页，不代表入口能连接 ISP 主机和端口 |
| ISP 出口 | 网站最终看到的代理出口 | 商家给的连接主机可能只是网关，未必就是网站看到的 IP |
| 静态 | 在产品约定条件下保持同一出口 | 仍要确认到期、维护、续费和主动更换时是否变更 |
| 独享 | 商家约定该出口供你单独使用 | `Private` 等产品名含义因商家而异，必须核对产品条款 |
| SOCKS5 / HTTP 代理 | 连接商家出口所用的协议 | 协议和端口必须对应；不能把 HTTP 端口直接填入 SOCKS5 模板 |
| 策略组 | 在客户端里决定使用哪个节点或组 | 名为 `ISP-服务` 的组是规则的目标；不是 ISP 主机地址 |
| proxy-provider | Mihomo 从订阅加载的一组节点 | provider 键名不是订阅显示名称，也不是 rule-provider |
| FUP | 套餐的公平使用限制 | 标称不限量仍可能有流量、带宽或并发限制，需看细则 |

需要固定出口时，先确认目标用途确实需要它。固定出口本身不能证明服务可登录、账号安全或 IP 永远不变；购买判断仍需回到商家的条款与实际测试。

## 开始前准备好什么

先从 [Clash Verge Rev 官方 Releases](https://github.com/clash-verge-rev/clash-verge-rev/releases)安装适合系统的客户端；图形链式功能按 [官方教程](https://www.clashverge.dev/guide/proxy_chain.html)要求使用 v2.4.5 或更新版本。已经安装旧版 Clash Verge 的读者先确认产品名称和版本，不要直接套用 Rev 的菜单步骤。

| 信息 | 去哪里找 | 填到哪里 |
| --- | --- | --- |
| 可用的入口订阅和节点名 | 原入口客户端、订阅提供方 | 图形链的第一跳，或脚本的 `entryNodes` |
| ISP 连接主机 | 商家后台代理列表 | 脚本 / YAML 的 `server`，不要带 `socks5://` |
| SOCKS5 端口 | 商家的协议参数 | `port`，填整数；示例 `1080` 不一定适用于你的产品 |
| 用户名、密码 | 商家提供的代理认证参数 | `username` / `password`；可能与网站登录账号不同 |
| 认证方式 | 商家后台或产品文档 | 本仓库模板按用户名密码配置；仅白名单认证的产品需按商家说明调整 |
| 网站看到的出口 IP | 商家后台、客服确认和实际检测 | 用于验收，不应仅靠网关地址推测 |
| 本地混合端口 | Clash Verge 设置页 | 浏览器或命令行连接本机代理时使用；它不是商家端口 |
| 有效期、流量与换 IP 条件 | 订单、套餐规则 | 用于到期续费、用量与故障判断 |

如果使用 IP 白名单，链式连接 ISP 的是入口服务器：通常需核对入口的公网 IP，而非直接填写家庭宽带 IP。切换入口后也要重新确认商家的认证要求。

保存当前订阅和扩展脚本副本，记下客户端版本和当前可用入口。真实订阅链接与代理凭据只在本地填写，不要提交到公开仓库。

## 选择一种配置方式

| 方式 | 适用情况 | 你要准备什么 | 日后维护 |
| --- | --- | --- | --- |
| 图形界面 | 首次配置，希望少写代码 | 一个能用的入口节点与 ISP SOCKS5 URI | 查看链的顺序、目标服务策略选择；按 [官方教程](https://www.clashverge.dev/guide/proxy_chain.html)操作 |
| 扩展脚本 | 已有订阅，想保留原分流并添加指定域名 | ISP 参数及准确节点名，或 provider 键名 | 入口更名时同步修改；检查后续扩展有没有覆盖规则 |
| 独立 YAML | 能读 YAML，希望自己管理整份配置 | ISP 参数和返回 Mihomo 节点 YAML 的订阅 URL | 自行维护 provider、规则、DNS 与本地端口 |

首次配置只选一种，避免多层重复注入导致难以定位问题。脚本和独立 YAML 的所有替换项见 [示例说明](../examples/README.md)，具体客户端操作见 [Clash Verge 配置](clash-verge.md)。

## 每一步应该看到什么

1. **只测试入口。** 暂不添加 ISP，确认原订阅能连接并访问目标网页。入口失败先修入口。
2. **添加 ISP。** 填商家主机、对应协议的端口和凭据。独立模板使用 SOCKS5；如果商家只有 HTTP，先核实产品或按官方 HTTP 节点格式调整，不能只换端口。
3. **建立链。** 图形链按入口在前、ISP 在后排列。脚本 / YAML 中则是 `ISP-出口` 的 `dialer-proxy` 指向 `ISP-入口`。这个字段表示“连接 ISP 时经由哪个入口”，依据 [Mihomo 官方说明](https://wiki.metacubex.one/config/proxies/dialer-proxy/)。
4. **让请求命中链。** 脚本与独立 YAML 为列出的服务域名设置 `ISP-服务` 规则；图形配置需自行把相应服务组指向链。日常使用规则模式，并确认浏览器遵循系统代理。
5. **检查连接。** 访问目标网页，在客户端“连接”查看该主机名命中的规则及代理链。仅在代理列表看到了 ISP 节点还不够。
6. **核对出口。** 使用下一节方法让检测请求明确走 ISP，再比较商家确认的出口 IP。检测通过后恢复原日常设置。

如果原订阅没有目标服务策略组或对应域名规则，仅建立图形链不会自动添加分流。此时建议改选 [扩展脚本](clash-verge.md#全局扩展脚本)，按示例添加域名规则并在规则模式验证；不要因为代理列表出现链就认为目标请求已经使用它。

## 完成后的验收

| 检查项 | 如何验证 | 通过标准 |
| --- | --- | --- |
| 配置加载 | 查看订阅应用结果及内核日志 | 无未知节点、端口或配置解析错误 |
| 分流命中 | 访问目标服务，查看连接面板 | 目标请求命中预期规则，经过 ISP 出口及预期入口 |
| 实际出口 | 临时让 IP 检测请求也走同一链 | 检测结果与商家确认的出口 IP 一致 |
| 出口稳定 | 重新连接后再测；切入口时确认白名单仍有效 | 多次请求仍为预期出口；维护换 IP 等按条款核对 |
| 服务操作 | 按自己的用途测试登录、消息和文件等操作 | 实际需要的操作能完成，并记录未通过项目 |
| 订阅更新 | 更新一次原入口订阅并重新应用 | ISP 节点、规则和入口引用仍然存在且可用 |

**为什么普通查 IP 页面可能显示入口 IP？** 模板默认只把列出的服务域名送到 ISP；其他网页可能走入口。要测 ISP，脚本用户可临时将可信检测服务的主机名加入 `extraDomains`（只填域名，不填 `https://` 或路径），保存并重新应用；测完删除再应用。也可临时使用全局模式并将实际全局组明确选到 ISP 链，测完恢复规则模式和原选择。

“IP 检测通过”只能说明该检测请求使用了预期出口。桌面端、命令行或额外上传域名是否也被接管，要分别查看连接面板和实际操作。

## 停用、恢复和日常维护

- 图形链：把相关服务组切回原入口，按需要停用或移除自定义链，重新检查目标请求。
- 扩展脚本：恢复之前保存的脚本，或移除本次添加的脚本内容，再重新应用原订阅。若原有其他扩展，保留它们。
- 独立 YAML：切回之前保存的原配置；核对系统代理、规则模式和 TUN 是否恢复为原设置。
- 命令行：若曾设置当前终端代理变量，按 [配置文档](clash-verge.md#浏览器桌面端与命令行)中的命令取消，或关闭该终端。

日常记录套餐到期时间、流量余量、续费价和商家维护通知。入口名称、代理密码或商家出口变动后重新验收。遇到问题先按 [排查表](troubleshooting.md)确认哪一跳失败，再考虑更换产品。
