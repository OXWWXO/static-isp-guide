# 先跑通一条链：新手阅读路线

[← 返回首页](../README.md) · [术语与常见问题](glossary.md) · [详细配置](clash-verge.md) · [故障排查](troubleshooting.md)

目标很具体：让指定网站看到你购买的固定 ISP 出口，其他流量按原来的入口规则处理。

## 第一步：确认自己需要什么

| 你的情况 | 建议从哪里开始 |
| --- | --- |
| 只需要普通网页可用，没有固定出口要求 | 先看[入口指南](https://github.com/OXWWXO/VPN-suggestions)，验证现有线路 |
| 想买 1 个固定出口试用一个月 | 看[首页比较表](../README.md#providers)，核对目标国家的单 IP 总价 |
| 已有 ISP，不知道如何接入口 | 看[图形配置](clash-verge.md#图形界面配置) |
| 想保留订阅分流，只添加指定网站 | 看[扩展脚本](clash-verge.md#全局扩展脚本) |
| 已配置但不通 | 直接进入[故障排查](troubleshooting.md) |

固定、独享、住宅归属是不同属性。请让商家分别确认，而不是只问“是不是住宅 IP”。

## 第二步：付款前取得完整参数

把下面问题发给商家，或在官方后台逐项核对：

> 我需要【国家】的 1 个独享静态 IPv4 ISP，租期 30 天。请确认首次和续费总价、最低充值、税费、流量/FUP、并发、到期保留与维护换 IP 条款。它是否允许访问【目标网站】？请提供准确的代理协议、主机、端口、认证方式，以及连接失败时的更换/退款时限。

如果只看到“每 IP 单价”，继续查最低购买数量；如果写“不限流量”，继续查 FUP。拿不到目标用途与库存确认时，把这一家留作待确认项。

## 第三步：选择一种配置方式

| 方式 | 你需要准备 | 完整操作 |
| --- | --- | --- |
| 图形界面 | 已可用入口 + 商家参数 | [Clash Verge Rev 操作](clash-verge.md#图形界面配置) |
| 扩展脚本 | 原订阅真实节点名或 provider 键名 | [脚本说明](clash-verge.md#全局扩展脚本) · [示例文件](../examples/clash-verge-script.js) |
| 独立 YAML | Mihomo 节点 provider URL + 商家参数 | [模板说明](clash-verge.md#独立-yaml-模板) · [示例文件](../examples/mihomo-chain.example.yaml) |

一次只使用一种方式建立第一条可用链，先备份原配置。示例中的 `.invalid`、`CHANGE_ME` 都是占位符，不能直接连接；将填写后的文件仅保存在本地。

链路方向固定为：**设备 → 入口 → ISP → 网站**。代理协议按商家给的参数选择；网站使用 HTTPS 不表示 ISP 的代理端口也支持 TLS。

## 第四步：用四项验收

- [ ] 入口单独使用正常，目标请求确实出现在客户端连接面板。
- [ ] 指定网站命中 ISP 策略；临时将出口检测请求也走相同链后，检测结果与商家的出口一致。
- [ ] 实际完成需要的功能：登录、消息、上传或桌面端；没有测的项目记录“未测”。
- [ ] 更新订阅后规则和 ISP 节点仍在，重新连接后出口符合预期。

检测域名不一定默认走 ISP。临时将它加入脚本 `extraDomains` 或选择全局链，确认后恢复日常分流；详细步骤见[验证配置](clash-verge.md#验证是否配置成功)。

## 第五步：失败时按顺序缩小范围

| 检查层 | 问什么 | 保留什么证据 |
| --- | --- | --- |
| 本地接管 | 这个应用的请求进客户端了吗？ | 客户端版本、模式、请求域名 |
| 入口 | 入口本身能连接普通网页吗？ | 节点地区、时间、运营商 |
| ISP 连接 | 协议、端口、凭据、白名单和有效期对吗？ | 脱敏错误、商家参数说明 |
| 分流与出口 | 规则命中了哪条链，出口对吗？ | 策略名、出口是否一致 |
| 目标服务 | 失败是超时、认证，还是网页验证？ | HTTP 状态与提示文字 |

可以对照[客服中继案例](iproyal-relay-case-2026-10-16.md)，但不要把某一次案例的解决方式当作所有链路都必须使用的方案。
